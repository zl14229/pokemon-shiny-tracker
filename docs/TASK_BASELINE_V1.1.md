## 3. 单个 Task 状态机
`planned` → `in_progress` → `in_review` → `verified`；阻塞时 `blocked`，需改规格为 `needs_decision`。允许失败修复后返回 in_progress。只能由实际可追踪的代码、测试和文档记录将任务标为 verified；不能单凭生成了回答就标记通过。

## 4. 每个 Task 统一交付字段
ID、目标、影响范围、依赖及输入、实现摘要、影响文件、自动测试命令和结果、自我审查（含回归风险）、未验证项、Git commit、GitHub PR URL 与合并 SHA（完成任务必须具备）、最终状态、后续 Task。复杂更改先说明目标/范围/方案，再执行。

## 5. AI 自主执行与暂停条件
无需询问：普通模块设计、遵循规格的实现、测试失败修复、兼容性修改、小型重构、一般 UI 细节与文档同步。
必须暂停：改变冻结的功能规则/技术架构、删除或覆盖真实记录/生产库、无法安全合并的真实数据冲突、需要账号密钥或新增费用、未授权远程上传/部署及外部操作、无法验证并影响继续开发的阻塞。
严格执行：不绕过失败测试；无法验证写明未验证；不执行未经授权的破坏性命令；不将尚未核验的游戏资料当作事实；每一任务提交可追踪结果。Git 提交/推送权限以工作环境事先授权为准。

## 6. 已知待核验输入（并非范围未确定）
1. **GitHub**：原远程仓库已由用户删除，新仓库需要重建；T000 确认远程、权限、GitHub Actions、PR 保护能力和新初始提交；旧本地目录单独留备份，不沿用旧提交历史。
2. **PokéAPI**：核对 v2 实际数据覆盖、各资源的 ID 映射、中文名完整性、访问与缓存要求；仅将通过校验的值入库。
3. **52Poké**：确认官方名称和形态的数据使用方式，重新核实机器读取规则及许可；不可假定有无限制可用 API。
4. **Serebii / Bulbapedia / Pokémon Database / 官方**：逐游戏、逐来源核对获取路径、锁闪、遭遇率和闪光概率；未核准自动化权限时不得批量抓取。已确认字段、未知字段和来源冲突必须可见。
5. **Excel**：T012 读取真实样本，检查列映射、日期/次数单位及疑似重复；原始数据只读，先预览再导入。
6. **附件与发布**：T013/T014 验证文件限制与备份恢复；T025 核验 Windows 本地启动、SQLite 文件路径、生产发布条件和可回滚性。

## 6A. 数据源治理验收门槛
- T006：首次初始化后的基础资料可在无网状态正常查询；外部源异常不能导致个人记录损坏；不要求全部游戏遭遇数据。
- T016：至少验证稳定物种/形态映射、语言缺失回退、来源可追踪和数据覆盖率标识；前端不得把未知翻译当官方中文名。
- T026：可获取性与攻略完整性独立；方法与概率条件化；对于未知或仅传送目标，Random Hunt 默认不得将其作为“所选游戏直接可刷”候选。
- T027：对资料缺失的游戏提示已核实范围/候选数，而不是显示虚假的全量覆盖；随机过程只读取本地可追踪资料。
- T024：采集与入库分离，更新前审查差异，事务应用，保留可恢复的资料快照，不能修改个人收集历史。

## 6B. GitHub 开发交付门槛（ADR-015）
- Task 分支均从远程最新 `dev` 新建，推送、创建 PR 指向 `dev`；通过自动检查与 AI 自审后合并。
- GitHub 默认使用 Merge Commit；保留合并后分支。`dev`/`prod` 应由实际配置的分支保护或等效规则约束；个人仓库保护能力若受计划限制则记录退化方案，不虚报自动受保护。
- 第一版 `prod` 在 M3 正式验收和发布授权后建立；后续正式发布由 `dev` 经 PR 进入 `prod`，版本 Tag 与备份演练保持一致。
- 任务完成证据至少包含 PR 链接、CI/本地测试摘要、合并 SHA、ADR/文档差异；禁止为了连续执行绕过失败的 CI。

## 7. MVP 阶段明确排除
强制多设备同步、联网访问、用户登录、全游戏专属机制、全资料零缺漏、自动更新、完整会话计时器、完整转移历史、高级统计。通过 M3 可用后再逐步扩展。
