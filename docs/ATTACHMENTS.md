# 本地附件与链接（T013）

在闪光个体详情“附件与链接”上传文件或添加HTTP/HTTPS链接。每只个体最多100个有效附件/链接，每个文件1字节至10MiB。支持PNG/JPEG/GIF图片、PDF与UTF8 TXT，扩展名与检测内容须一致；图片头/尺寸校验限制单边10000、总像素2500万。其他格式、SVG/HTML、可执行文件和视频上传暂不支持；视频可用外部链接，不抓取内容或镜像站点。

文件位于 `${SHINY_DB_PATH}.files`（实际数据库路径后加`.files`），与数据库一一对应，必须在Git仓库外且为真实私有目录（0700），新文件0600；不接受根目录符号链接或宽松权限。系统生成随机不可变存储键，独占创建，不把原文件名用作磁盘路径；拒绝分隔符、控制字符、Windows保留名和非法字符、隐藏名、过长名称等。内容访问使用Go rooted filesystem，拒绝逃逸/符号链接、非普通文件和哈希/大小不符，不输出磁盘路径或原始错误。

上传先完整写入/fsync独立新文件，再事务创建所属个体的元数据；数据库失败只清理本次未关联的新文件，不碰已有数据。同名上传不会覆盖旧文件。崩溃可能留下无元数据孤立文件，本版不自动物理清理，备份只包含数据库引用的文件。版本4仅新增attachments表/约束/索引，不重建旧实体身份。

**删除为软删除关联**：从正常列表和内容接口移除，文件暂保留供历史与并发一致性备份，不立即释放磁盘。本版没有物理清理或回收站界面。个体软删除也保留其元数据/文件；不要手动删改私有文件目录，否则完整性检查与备份会失败。T014备份包含引用的文件及软删除元数据，原始Excel、孤立文件与外部链接的网页/视频内容不包含；仅保存链接元数据。

图片经完整性核对后可直接查看；PDF/TXT强制下载，全部文件有nosniff/no-store头。链接只允许无账号密码的HTTP/HTTPS URL，仅保存/打开，服务端不访问；前端再校验协议、用noopener/noreferrer打开。未知或损坏响应拒绝显示，失败保留输入并提示。上传/添加链接结果不明时锁定重复写入，先刷新列表核对名称、时间与大小；不自动重试。目录权限/检测头不等于杀毒或完整媒体格式审计。

## API

- `GET /api/v1/shiny-records/:id/attachments`：活动个体的全部有效附件/链接（最多100项），ID稳定。
- `POST /api/v1/shiny-records/:id/attachments`：multipart一个`file`，原始filename校验后落随机存储键；201 data附件。
- `POST /api/v1/shiny-records/:id/links`：JSON name/url；201 data附件。
- `GET /api/v1/attachments/:id/content`：活动文件/所属个体存在时返回完整性校验后的内容，已移除/个体已删除返回404；链接不是文件。
- `DELETE /api/v1/attachments/:id`：软删除关联；200 `{"data":true}`；不会物理删除文件。

元数据含kind、name、media_type、sha256、size_bytes、url、所属个体与系统审计时间；不向普通API暴露存储键或绝对路径。沿用统一错误契约，拒绝外部Origin/跨站请求，不开放CORS。不得将个人文件放进源码或上传GitHub，附件原件均不随开发提交。

测试只用内存生成PNG和匿名文本、隔离SQLite/目录，覆盖路径/链接/非法名/MIME/大小/图片尺寸/根目录权限/损坏/无覆盖/失败清理/软删除保留/配额及HTTP、组件Client和真实浏览器。Windows原生运行与物理清理不在本Task验收范围。
