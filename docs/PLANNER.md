# Hunt Planner（T027）

入口 `/#/planner`。只读取本地已核实资料，无运行时外站抓取。初始资料仍只有朱、紫各 12 个目标，来源、版本与缺口见 [HUNT_DATA.md](HUNT_DATA.md)。不能将这一子集当作完整游戏目标池。

## Random Hunt 口径

- 选择 1–20 个不同版本，同一收藏体系；保存位置不可抽取。物种或持久形态，数量 1–100。
- 默认全系列历史未获得；可改为所选版本的原始获得记录中未获得。多个选定版本作为同一范围：任一选定版本已获得就排除目标。当前位置不代替原始获得游戏。
- 复用 T017 图鉴历史证明引擎：当前／原始明确物种和形态、进化与形态历史；软删除排除，不根据旧注册快照推断。交换与已不持有仍是历史获得，未记录形态不补推。
- 默认在同收藏体系内排除所有版本中进行中的相同目标。物种模式按物种；形态模式排除相同形态及未指定形态的同物种 Hunt。可明确取消此默认过滤。
- 候选必须具有已应用的本地批次、来源和映射一致、verified + confirmed_available + direct_hunt=yes，且形态 inclusion=included。M4 的单独可获取性条目未证明直接可刷，不自动当作候选。
- 先按唯一目标均匀抽取，不放回；再在该目标可刷的不同版本间均匀选择。同物种多个形态／多个版本不增加目标权重。生产使用 crypto/rand；没有概率加权。
- 可刷性与攻略完整性分开。方法缺失显示待完善，遭遇率／闪光率可独立未知；有值必须显示条件和来源，不跨版本套用。
- 不足时返回实际数量；空池返回 0，不能保存空结果，不补入未知、锁闪或仅传送目标。界面说明逐游戏核验条数、可用目标、排除数量及资料版本。

## 保存与 Hunt

生成会在 SQLite 保留草稿、生成时间、规范化规则、覆盖情况及完整来源快照，不创建 Hunt；草稿不出现在“已保存计划”。点击“保存本次结果”后进入历史，刷新和离线读取仍可访问 `/#/planner/plans/ID`。未保存草稿留作生成审计，不自动删除；本任务不提供草稿清理器。

生成请求带 request_id，相同标识和规则重试返回同一草稿；同一标识改变规则则拒绝。保存幂等。只有逐个明确点击“转为 Hunt”才创建任务，保存的目标与游戏不会重新随机；同一目标重复操作返回原关联 Hunt。

转换前再次验证当前本地来源与缺失／进行中规则。已撤回或不再符合条件的目标不能自动转换；原计划仍保存生成时的历史证据。可通过接口关联符合目标和游戏、正在进行的既有 Hunt；不会因关联而复制 Hunt。转换不新增 ShinyRecord、不改变收藏。

schema 8 新增 hunt_plans、hunt_plan_targets：稳定外键、每计划位置／唯一目标约束、JSON 规则与证据快照。备份／导出含两表；测试证明新目录恢复后快照、目标和 Hunt 关联保持一致。旧备份按对应旧版恢复新目录，再用新版升级。

## API

- `POST /api/v1/planner/pool`：`{"rules":{"game_ids":[3,4],"dimension":"species","pool":"all_missing","count":2,"exclude_active":true}}`；只读，返回 candidates、coverage、规范化 rules。上述内部游戏 ID 为当前种子示例，客户端应从游戏接口读取。
- `POST /planner/random`：同上加 `request_id`（8–80 位字母／数字／连字符）；返回 data=草稿计划（201），可安全重试。
- `GET /planner/plans?limit=20&offset=0`：已保存列表、稳定 ID 倒序，limit 1–100。
- `GET /planner/plans/:id`：完整计划、规则、覆盖快照及有序目标。
- `POST /planner/plans/:id/save`：空 JSON 对象，幂等保存。
- `POST /planner/plans/:id/targets/:target/hunt`：空 JSON 对象创建 Hunt；或 `{"hunt_id":ID}` 关联既有 Hunt。

省略的路径均在 `/api/v1` 下。筛选无效为 400，状态变化或重复目标冲突为 409，来源／映射不一致为 503 reference_unavailable。响应未核实来源不回退成可刷；前端只展示预定义错误，不回显内部异常。请求限制、JSON 严格字段和同源限制沿用本地 API 边界。

## 验证范围

专项测试包括 30,000 次固定随机序列的多版本偏权反例、去重与不放回，原始／当前游戏、历史进化、未知形态、跨版本进行中、负面／未知／冲突状态、方法与概率未知、空池／不足、来源撤回、幂等、数据库失败原子性及备份恢复。合成补充形态和负面状态只用于测试，不进入正式来源覆盖数量。

## T028 Bingo

`/#/planner/bingo` 创建 3×3／5×5 卡片，已保存卡片使用同一计划历史和详情入口。默认新获得、时间精度、人工时间核验、重抽与封存规则见 [BINGO.md](BINGO.md)。正式 12 个唯一目标不足 5×5 时必须拒绝，不生成部分卡片。
